# Changelog

## [0.2.8] - 2026-10-18

### Fixed

- **`check:citations` checks every `excerpt`, including `alsoBasis`.** The gate read only the first excerpt per rule; this pack had additional `alsoBasis` quotations that were never checked. It now reports the complete segment count.

## 0.2.7 - 2026-10-18

- Fix: a rule that executed and found no difference is no longer placed in `skipped`. The report view labels only genuinely unexecuted rules as “未执行的检查”; `skippedCount` no longer counts executed-clean rules.


## 0.2.6 - 2026-10-17

- Compatibility: declare `engines.dsh` `>=0.2.1-0 <0.3.0`; move `@deepseek-ai/dsh-*` devDependencies to `0.2.1-rc.2`; add `@deepseek-ai/dsh-working-directory`.
- Docs: the compatibility table no longer claims `engines.dsh` is undeclared; drop the retired `both` tool mode.


## 0.2.5

- **`MR-001` is an `error` again, corrected on evidence.** Its only basis is the note at the foot of
  **附件1「住院病案首页必填项目列表」** of 国卫办医发〔2016〕24号. On 2026-10-07 that rule was
  **downgraded to `warn`** because the attachment was recorded as a PDF this environment could not
  decode — and under this family's rule a clause that cannot be read does not block a workflow, so the
  downgrade was right at the time.

  **The attachment does have a text layer.** It was read on 2026-10-13: 328 pages, 205,847 extractable
  characters, **no OCR**. The note is verbatim
  「注：必填栏不能为空项，没有可填写内容时填写“-”」 — the same wording the rule already carried. The only
  difference is that the PDF prints curly quotes where the rule uses straight ones, a typographic
  difference recorded in the evidence file rather than papered over.

  ⚠️ **The source tier is stated plainly in the evidence.** `www.nhc.gov.cn` returns **HTTP 412** to
  automated requests (measured, and the site root is 412 too), so the text came from a
  **河南省病案质量控制中心** compilation — the very URL this rule's `source` has always carried, and the
  same tier as the 高校／省级 reprints the other fourteen rules rely on. It is therefore not a reason to
  treat `MR-001` differently, but it is not the publisher's own text either, and the reader is told so.

  New evidence file: `rules/evidence/clause-verification-homepage-attachment1.md` (source, attempt log
  with status codes, the verbatim text, and the quote-character difference).
  The `MR-001` rows and the "why it was `warn`" section were updated in all five READMEs together, which
  `check:readmes` requires.

  No rule was added or removed: still 15 rules across `MR-001`..`MR-015`. The only severity that moved
  is `MR-001`, `warn` → `error`.

## 0.2.4

- Add a demo card to the README: one terminal shot of this plugin's real output
  over its own test fixture, plus the DSH Market badge.

  The card is generated by running this repository's check core over a committed
  fixture and rendering the report it returned, so the findings, rule ids, cited
  documents and "not obtained" notes are the plugin's own output rather than an
  artist's impression. In a family whose claim is that it never fabricates a
  citation, a hand-drawn screenshot would undercut the thing being demonstrated.

  Added to all five READMEs together, which `check:readmes` requires.


## 0.2.3

- Rework the README first screen. The H1 now names what the plugin checks rather
  than repeating the package name, and a question-and-answer table and a standards
  table come before the boundary paragraph.

  The substance is unchanged and the boundary paragraph is verbatim: in a
  compliance tool that paragraph is what stops a wrong "pass" being read as
  approval, so it moved rather than shrank. What changed is the order - a reader
  or an extractor previously met eleven badges, an install command and a
  disclaimer before learning what the plugin does. The Q&A rows are derived from
  each plugin's own rules and the standards table from the rule pack's
  `document`/`number` fields, so no answer and no standard is hand-typed.

  All five languages were restructured together; `check:readmes` holds them to the
  same section count, install command and configuration keys.

## 0.2.2

- Ship `CHANGELOG.md` and `SECURITY.md` inside the package. `files` is an
  allowlist and neither was on it, so no release note had ever reached anyone
  who installed this package, and npm had no changelog section to show.
## 0.2.1

- Citation pass: every `excerpt` was checked against this repository's own
  `rules/evidence/` record, and the record was completed for the clauses the
  rules quote.
- Adds `rules/citations-baseline.json`, which the `check:citations` gate reads:
  it lists any excerpt not yet traceable to the evidence, and that list can
  only shrink.
## 0.2.0

- Release infrastructure brought to the family standard: `verify:self-contained`,
  `check:lockfile`, `check:readmes` and `check:citations` gates, a `prepublishOnly` that
  re-runs the whole chain, SECURITY.md, dependabot, and the OpenSSF Scorecard workflow.
- `check:citations` enforces the rule this pack's own header states: every `excerpt`
  must be a verbatim quotation, findable in `rules/evidence/`. Rules that are not
  traceable yet are listed in `rules/citations-baseline.json`, and that file can only
  shrink - anything new has to be sourced before it can land.
- The README install command now names the published package instead of a local tarball.
- Five-language READMEs hold the same section count and the same configuration keys.
- Rule pack: 15 rules across MR-001..MR-015.
- Licensed Apache-2.0.
